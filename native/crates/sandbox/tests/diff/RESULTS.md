# The differential against today's Docker sandbox: last results

`tests/docker_diff.rs` with `tests/diff/today.js` runs today's `server/sandbox.js` on Docker, which makes containers named as the app's own (`mcb-v3-<scope>-<chat>`, `mcb-net-<scope>-<chat>`) from `localhost/mcbench-sandbox:<hash>`. Those names are fixed in `server/sandbox.js` (`IMAGE`, `containerName`), so it no longer runs on the owner's machines: both refuse unless `MCBENCH_I_OWN_THIS_DOCKER=1` is set (a CI machine). The evidence of its last runs is kept here.

Runs on adipc, 2026-11-17 03:28 to 03:47, branch `s3-sandbox` (`b2e653a2` to `f86a0712`), rootfs `addd26de…1368`: three full runs gave 98, 98 and 97 of 106 cases identical (wall times, curl's milliseconds, dd's timing line and bash's job pids masked). Every other case differed only as below; the stderr ordering cases differ in 3 to 5 cases per run because today's ordering is a race.

| Case | Today (Docker) | Native (bubblewrap) | Cause |
|---|---|---|---|
| stderr, interleave, interleave-python, many-lines-mixed, net-stderr | stderr reordered, or carried into the next command's transcript | stdout and stderr in the order written | today's `docker exec` gives two pipes read as they arrive, and the sentinel on stdout overtakes stderr; here one pipe. Changes what a model reads: the owner's decision |
| emoji-truncated | a lone surrogate at the middle cut | U+FFFD there | Node's string keeps the lone surrogate (JSON writes `\udXXX`); Rust's String cannot |
| id | `uid=1000 gid=1000 groups=1000` | `… groups=1000,65534(nogroup)` | kernel: an unprivileged user namespace cannot drop supplementary groups |
| unshare | `unshare failed: Operation not permitted` | `unshare failed: No space left on device` | `--disable-userns` sets `user.max_user_namespaces` to 0; Docker's seccomp answers EPERM |

Since the refused calls' filter (2026-11-18, branch `s3-vsock`; `linux::refused`) the `seccomp` case no longer differs: every program of a box carries one seccomp filter and reads `Seccomp: 2` and `Seccomp_filters: 1`, as in today's container (the 106 cases through the Linux implementation on adipc that day: 105 identical to the reference of 2026-11-17, the one difference this case). The run against Docker itself was not repeated for it.

Since the box's own limits (2026-11-17, branch `s3-shellwire`; `linux::keeper::RLIMITS`) one more case differs from the record, and on purpose: `signal-segv`. Today's container printed `Segmentation fault      (core dumped) bash -c 'kill -SEGV $$'` on adipc, because Docker gives a container the machine's core dump handling and adipc pipes cores to systemd-coredump; a box has core dumps off on every host and prints `Segmentation fault      bash -c 'kill -SEGV $$'`, as the macOS VM did already. `ulimit-n` stays identical (65536, today's container's on adipc, now the box's own). Docker was not run again: the comparison went through the record (the last run's report, whose identical cases had the native answers of the Linux reference before the change): 96 identical, the 9 differences above unchanged, `signal-segv` new.

The 98 identical cases cover stdout and stderr, large, binary and incomplete-UTF-8 output, middle truncation, timeouts (fractional and clamped), background jobs, non-zero exits, signals, cwd, environment and functions carried and reset, files in `/work`, the read-only root, `/tmp` and `/dev/shm` (sizes, noexec), the memory, task and `/tmp` limits, the cgroup files, capabilities, the tools of the image, the networked command (DNS, https, the LAN and metadata refused with curl 7, UDP `EPERM`, IPv6 off, no state kept, background jobs ended, timeout), the write-disabled shell and its storage messages, `view_image` (the PNG's bytes, and its three errors), `removeWorkFiles`, and the disabled network's refusal.
