# The chat screen's accessibility contract

Every platform is checked against this table: in process by `cargo test -p mcbench-ui --test contract` (GPUI's test platform; the AccessKit tree read through `accesskit_consumer` as the adapters read it; runs on every host), on Linux by `verify/linux/` (AT-SPI, X11 and Wayland), on macOS by `verify/macos/` (the AX tree in the guest VM), on Windows by `verify/windows/` (UI Automation in the Windows VM). The dev binary `mcbench-ui-dev --fixture gate` shows every row.

The AccessKit role is what the app sets. The AT-SPI column is what AccessKit's Linux adapter (`accesskit_atspi_common` 0.19.1 and `accesskit_unix` 0.22.1, patched in `native/vendor`) makes of it, as `verify/linux/check_tree.py` read it (`verify/linux/expected/gate-tree-open.json`). The macOS and Windows checks add their own columns.

## Choices, and why

Message rows are `Article`, the role the brief names; AccessKit maps it to the AT-SPI article role. The model's turn of work (the `Worked` fold and the live tool stack) is an article too, described `work`, so a next-article command visits every row in reading order.

The folds and the tool-call rows are disclosure buttons (`Button` with `expanded`), as today's page draws them with `<details>`/`<summary>`; the reasoning is one of these folds rather than a group, because only a button carries the expanded state on all three adapters.

The transcript is a `Region` (an AT-SPI landmark), not a web area or a document. Tried on Linux on 2026-11-17 (`verify/linux/evidence/web-area-experiment.txt`): as `RootWebArea` or `Document`, with a patch adding the AT-SPI Collection interface, Orca 51.1 entered browse mode on the transcript and H, K and L found headings, links and lists, but only among the rows the virtual list has in the tree. On the long fixture (400 messages, a heading every fourth) H found "Step 395" every time and wrapped. Browse mode also took Up and Down from the app's message navigation and read "blank", because AccessKit has no Hypertext interface for a caret to walk. The same limit holds for VoiceOver's rotor under an AXWebArea and for NVDA's browse mode: a screen reader's document view of a virtual list holds only what is laid out. The region keeps the app's own keys (Up and Down by message, the message's text read on focus), and the Collection patch was dropped.

A table offers AT-SPI's Table interface and its cells TableCell (patch 29 of `native/vendor/README.md`): row and column counts, the cell at a row and column, each cell's row, column, spans and column header, from the same zero-based indices UIA's Grid and Table patterns read (patch 26).

Paragraphs, headings, code and cells hold their text as AccessKit text runs, one per visual line segment and per direction, each with its characters' lengths, positions, widths and word starts, its text direction, and the line break in the run that ends its line. AccessKit 0.38 offers text ranges (the AT-SPI Text interface, the macOS text range attributes, the UIA Text pattern) only on text inputs, `Label`, `Document` and `Terminal`; `native/vendor/accesskit_consumer` adds `Paragraph`, `Heading`, `Code`, `Cell`, `ColumnHeader` and `RowHeader` (patch 3 of `native/vendor/README.md`). AccessKit measures nothing in a run without a direction, so every run states one.

A link is a synthetic `Link` node inside its paragraph with its own text run, so the paragraph's text reads through the link; the focusable box over the link's first line has no node of its own, and the paragraph reports the link as focused when that box holds keyboard focus (patch 1).

The transcript is a virtual list: only the rows on screen, the row just above them and the row just below (patch 31), plus the focused row, are laid out and in the tree, so a screen reader's own next and previous item always find a neighbour, even when one message fills the screen. Every message carries its position in the set and the set's size (all rows, counted from 0 as AccessKit does; the adapters add 1), so a screen reader says "message 3 of 12" whether the others are laid out or not. The transcript offers scroll up and scroll down (a page each) to assistive technology. Up and Down (and Home, End, Page Up, Page Down) move the current message, scroll it into view and focus it, so the next message enters the tree before the screen reader reads it; the list keeps the focused row laid out while it is scrolled out of view. Copying never depends on layout: the selection's text comes from the rows' model, so Ctrl+A then Ctrl+C copies rows that were never laid out.

A cached GPUI view keeps its accessibility subtree when its frame is reused (patch 9; `contract::a_cached_view_keeps_its_accessibility_subtree`).

## How a screen-reader user reads a long answer

Up and Down move from message to message; each message takes focus and is read whole by its name: its author and its text, with code blocks and tables standing as their kind and size. Right moves into the current message, to its first block; Right again to the next block, Left to the previous, and Left from the first block back to the message. A block is a paragraph, a heading, a list, a code block, a quote, a table or an image at the message's top level; each is a focusable group (not a Tab stop) named by its kind and then how it reads (`heading level 1, A lamp on a lever`, `paragraph, …`, `list, 3 items, …`, `quote, …`; a code block `code, rust, 5 lines` and a table `table, 4 rows, 3 columns`, whose content is reached by entering them: the table's own navigation and the code's text). No block has a description. A rule is not a stop. Up and Down from a block move to the previous or next message. Tab from a message or a block walks the message's parts (folds, tool rows, links, Copy code buttons) as before.

With Orca on Linux (focus mode, the default in the app): the arrows reach the app, and Orca reads each message and each block once, by its name (`verify/linux/check_orca.py` asserts it; `verify/linux/evidence/check_orca-x11-orca-speech.txt`). A block's content is not read again after its name, as a message's is not. Inside a block, Orca's own review keys (flat review, KP_7 to KP_9) read it line by line and word by word from its text runs.

## Open after the gate

These are known and not fixed at the gate; they are the first work of the next milestone, each with its platform recheck.

(a) NVDA does not speak the error text on the fatal screen: the text sits inside the alert, not in its name. Done by shell-base: the alert's name is `mcbench-lite stopped on an error: <message>` (`contract::the_fatal_screen_reads_its_message_and_focuses_quit`); NVDA's recheck is the Windows platform agent's. Rechecked on Windows at s4-chat 057edbae: after a title-bar activation NVDA says "mcbench-lite — stopped, window", "mcbench-lite stopped on an error: store-unreadable:disk-full", "Quit, button" (`verify/windows/evidence/shell-chat-057edbae/nvda-fatal.txt`).

(b) A streaming answer raises one Name change per frame on its message and on its blocks (104 in one turn), since the name holds the text. Done by shell-base: while a message streams it is named by its writer alone (`claude-opus-5-5`) and its block being written by its kind alone (`paragraph`, `list`); a block settles when the next one begins and takes its full name then; the message takes its full name when the turn's answer settles. A reader with focus on a streaming message hears the writer's name, then nothing while it streams, then (the name changing once) the whole answer; the status region announces it as before (`open_items::a_streaming_answer_keeps_its_names_until_it_settles`).

(c) An image's reported rectangle is its element's box, wider than the picture drawn. Done by shell-base: the image's node is in a row of its own and as wide as the picture plus its focus ring (`open_items::an_images_node_is_as_wide_as_its_picture`: 240 to 246 for the 240 px fixture picture, was 420).

(d) Narrator's scan mode reads a heading twice (the block group, then the heading inside it), and VoiceOver hears a message's text again as its first block's name on entering the message. Left as it is (shell-base): both come from one rule that the other readers need. A block is read by focus (Right and Left) only through its group's name, so the group's name must hold the text; the heading or paragraph inside it must hold the same text as text runs, or reading by word and character (Orca's review keys, VoiceOver's and Narrator's text navigation) is lost. A scan mode walks every node and so reads both; AccessKit 0.38 has no way to mark the group's name as taken from its contents (which would let a scan mode skip it), and dropping either node loses one way of reading. Likewise a message's first block repeats the message's name because both are names, and the message's name is what every reader speaks on focus.

(e) In the macOS guest, for 10 to 30 s after launch the app falls behind scroll events and neither the AX tree nor the screen updates (gate-mac's FOR-GATE.md section 24; not traced). Traced on adipc by shell-base (`verify/linux/check_perf.py launch-scroll`: right after launch, with an AT-SPI client attached, 120 wheel clicks over the 400-message chat, each timed on the app's clock against its arrival): not reproduced on X11 or Wayland in six runs; wheel events reach the app within the clock's resolution of being sent and are painted in 13 ms (X11) and 5 ms (Wayland) at the median. One run in six (X11, with `--a11y-dump`) stalled once for 1.25 s about 5 s after launch, with the wheel events queued behind it; none without the dump. The dump, which every platform's checks run with, parsed, compared, pretty-printed and wrote the whole tree on the interface thread every 100 ms while the tree changed, which is every frame of a scroll; that work now runs on a background thread, and the part left on the interface thread (making the tree's JSON) stays under 16 ms here. On the Mac's real hardware (the rig's virtual display, 12 launches with each frame source, `CAMetalDisplayLink` and `CVDisplayLink`, and a three-minute streaming turn) the window never stopped drawing: no update, key or wheel event waited over 1 s for its frame. The guest's freezes are the guest's paravirtual display, not the app; no vendor patch (the plan's section on the gate's open items has the table).

(f) The contract suite takes about 100 s, because one test streams 30 turns at the stand-in's real rate. Done by shell-base: under test the stand-in streams at zero delay (`--rate-ms` sets the dev binary's pace); the suite takes 11 s on adipc.

## Settings (settings agent)

A press from assistive technology (AccessKit's Click) on a `controls::Button`, a `controls::Toggle` and every control of Settings and the setup screen now runs the control's own action. GPUI's fallback for a Click without a handler is a pointer press at the element's centre, which does nothing for a control scrolled out of its pane (the first runs of `check_settings.py` found the shortcut keys dead to a reader's press) and could press whatever is drawn at that point instead. A reader's press therefore no longer moves keyboard focus to the pressed button (a pointer press did); Settings' opener is what had focus when they opened. A pane shown by any control (a pointer, a key, a reader's press) puts keyboard focus on its tab, as opening Settings does.

The panel takes the stylesheet's sizes (`.settings-panel.sidebar`): at most 1100 by 780, 32 px inside the window's width and 48 inside its height; at 980 px wide and below, 32 px inside the height, the navigation above the pane (at most 38% of the height), rows stacked and the models' ids hidden.
